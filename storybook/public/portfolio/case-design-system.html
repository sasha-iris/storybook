The library

Where this came from

The design system already existed in Figma, and it is the product's, not mine. What did not exist was the version anyone could build from: developers and a low-code environment were both consuming a stylesheet that had drifted from the Figma file, with no documentation tying the two together. This repository is that system turned into code, documented against the CSS the product ships — assigned work, not a side project.

Problem

A story could be drawn with inline styles and no library class in the markup: a picture of a component, not the component. Copying it gave a developer something that would not ship.

So I checked all 447 shipped classes against the stories by computed style, not by eye. Twelve families failed and were rebuilt.

Decisions

  • Deleted components that were never designed A KPI card, datepicker presets, a metric card, several select and search types existed in the docs but not in Figma. Rule since: not in Figma, not in Storybook.
  • Did not delete CSS that looked orphaned 33 rules with no story and no page using them. The low-code environment consumes the same file and I could not see inside it. Documented as orphaned instead.
  • Fixed accessibility in the token, not on the page Success green measured 3.0:1 on white; the token moved to #007a55, with the reason recorded beside it. Page-level fixes would not have travelled.
  • Kept the two CSS files in lockstep Preview and export consume different files. Auditing the pair found six token conflicts — one, a blue-versus-purple --color-bg-primary, was breaking form checkboxes.
  • Real content in every story Placeholder text hides truncation, wrapping and spacing bugs. Written into the story patterns next to the argTypes template.

What building on it exposed

Building on it is what exposed the gaps: an unusable drawer, a progress bar with no danger variant — so a broken state wore the chart palette's trend-down pink — and two tokens below AA at the sizes pages actually used.

Adoption

  • Three consumers, one source Storybook preview, the production CSS bundle, and the low-code environment all read the same stylesheet. Keeping them identical is a rule with a pre-push check, not an intention.
  • Coverage measured on the running page, not claimed Every element carrying a class is checked against the 616 the library defines. Numbers below. Where coverage is low it is a recorded decision, not drift.
  • A React wrapper per component, with stated boundaries Each says what to use it for, what not to, and which existing component it replaces. Charts and data grids are declared out of scope and point elsewhere.

Segments is low on purpose: the product owner asked for a second visual language, so it ships its own stylesheet. A system that reports 16% where 16% is true is one you can plan against.

What I would change

The drawer is still unusable and 33 rules are still marked orphaned rather than deleted. Both need visibility into the low-code environment I do not have.
