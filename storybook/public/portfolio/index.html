How I work

I measure before I argue

When a layout question comes up, I build both versions and measure them. One of the case studies above records an argument I made in a review, that a column layout gives the eye a rail. The measurement threw it out: both layouts aligned at the same left edge. The proposal it supported went with it.

Prototypes use only classes that already ship

Every prototype page uses only classes that exist in the shipped CSS. When a page needs something the library does not have, that is a finding about the library, not a licence to invent a class. Accessibility fixes reached the design system that way, including a success green that measured 3.0:1 on white.

Three reviews before a stakeholder sees it

Business analysis against the brief, a usability and design-system pass, and risk-based QA in the running page — plus measured contrast, not assumed contrast. On the segments work those passes closed 48 defects before the review call.

A prototype never invents data

Prototypes get read as specification. So segments that were never calculated show “no data” instead of a plausible number, and an estimated channel split says on the screen that it is estimated.
